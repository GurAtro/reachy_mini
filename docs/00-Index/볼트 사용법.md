# 볼트 사용법

이 볼트는 `docs/` 폴더 자체입니다. Obsidian에서 **"폴더를 보관소로 열기"** → 
`~/orca/projects/Reachy/docs` 를 고르세요.

노트가 코드와 같은 저장소에 있으므로, 커밋 하나에 "무엇을 고쳤는가"와 "왜 고쳤는가"가
함께 남습니다.

## 폴더

| 폴더 | 무엇이 들어가는가 | 언제 만드나 |
|---|---|---|
| `00-Index` | [[Home]] 대시보드, 이 문서 | 거의 안 늘어남 |
| `10-Modules` | 코드 서브시스템 하나당 한 장 | 새 모듈이 생기면 |
| `20-Tasks` | 구현 작업. `T-###` | 할 일이 생기면 |
| `30-Decisions` | 결정 기록(ADR). `ADR-###` | **되돌리기 어려운 선택**을 할 때 |
| `40-Log` | 날짜별 작업 로그 | 매일 (데일리 노트 단축키) |
| `50-Reference` | 변하지 않는 참고 자료. `R-` | 드물게 |
| `_templates` | 새 노트 틀 | — |

## 노트 만들기

**작업**: `Ctrl/Cmd+P` → `Insert template` → `구현 작업`
**결정**: 같은 방법으로 `결정 기록`
**로그**: 데일리 노트 명령 (`40-Log/YYYY-MM-DD.md`가 템플릿과 함께 생성됩니다)

## 연결 규칙

이 볼트가 굴러가는 건 이 네 가지 덕분입니다. 지키지 않으면 [[Home]]의 표가 비어 보입니다.

1. **작업의 `area`는 모듈 노트를 가리킨다** — `area: "[[M-robot 로봇 제어]]"`.
   그러면 모듈 노트 하단의 표에 그 작업이 자동으로 뜹니다.
2. **작업의 `files`는 실제 소스 경로를 적는다** — `reachy/robot.py` 처럼.
   나중에 "이 파일 왜 이렇게 됐지"를 역추적하는 유일한 실마리입니다.
3. **결정은 링크로 인용한다** — 작업 노트에서 `[[ADR-001 ...]]`을 걸면,
   결정 노트의 백링크 패널에 "이 결정이 실제로 어디에 쓰였는가"가 쌓입니다.
4. **삽질은 로그에, 결론은 참고 문서에** — 같은 걸 두 번 겪지 않으려면 둘 다 필요합니다.

## 상태 값

`status`는 [[Home]] 쿼리가 읽습니다. 오타가 나면 표에서 사라지니 이 값만 쓰세요.

| 종류 | 허용 값 |
|---|---|
| 작업 `status` | `todo` · `in-progress` · `blocked` · `done` |
| 작업 `priority` | `P0`(당장) · `P1` · `P2` · `P3` |
| 모듈 `status` | `stable` · `wip` · `unverified` |
| 결정 `status` | `proposed` · `accepted` · `superseded` |

## git 히스토리 연결

```bash
python docs/_scripts/sync_log.py            # 오늘 커밋을 오늘 로그 노트에
python docs/_scripts/sync_log.py 2026-08-06 # 특정 날짜
```

그날의 커밋 목록을 `40-Log/YYYY-MM-DD.md`의 `## 커밋` 섹션에 채웁니다. 여러 번 돌려도
같은 자리를 덮어쓰므로 중복되지 않습니다. 손으로 쓴 부분은 건드리지 않습니다.

작업 노트의 `commits:` 항목에 해시를 적어 두면, 그 작업이 실제로 어떤 커밋으로
끝났는지가 남습니다.

## 플러그인

[[Home]]의 표는 **Dataview**로 그립니다. 이미 `docs/.obsidian/plugins/dataview/`에
설치돼 있고 활성화되어 있습니다. 표가 코드 블록 그대로 보이면 설정 → 커뮤니티 플러그인에서
Dataview가 켜져 있는지 확인하세요.
