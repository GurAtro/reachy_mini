# ADR-003 연결 실패 시 mock 폴백

## 맥락
로봇이 없어도 개발이 되어야 합니다. 그리고 데몬이 안 떠 있는 상황은 실제로 자주
생깁니다 → [[R-데몬과 연결]]

## 선택지
| 안 | 장점 | 단점 |
|---|---|---|
| 연결 실패 시 예외로 중단 | 문제가 즉시 드러남 | 로봇 없이는 아무것도 못 돌림 |
| 조용히 mock으로 강등 | 하드웨어 없이 전체 흐름 개발 가능 | **고장을 정상으로 착각하게 됨** |

## 결정
`Robot._connect()`가 실패하면 mock 모드로 내려가고, 앱은 계속 실행합니다.

## 근거
이 프로젝트의 대부분 작업(LLM, 도구, STT, TTS)은 로봇과 무관합니다. 하드웨어를
필수로 만들면 개발 속도가 하드웨어 가용성에 묶입니다.

## 결과와 대가
**이게 이 프로젝트에서 가장 위험한 설계입니다.** 로봇을 연결했다고 생각했는데 mock으로
돌고 있으면, 모션 코드를 고쳐도 아무 변화가 없고 원인을 엉뚱한 데서 찾게 됩니다.

완화책:
- `[Reachy] Connected.` 로그를 확인 절차로 못 박았습니다 → [[R-단계별 구동 절차]]
- `[Reachy] MOCK mode` 로그를 트러블슈팅 표 첫 줄에 뒀습니다 → [[R-문제 해결]]

**아직 부족합니다.** `reachy.enabled: true`인데 연결에 실패한 경우는 "의도적 mock"이
아니라 "고장"입니다. 이 둘을 로그에서 구분하는 게 낫습니다 — 전자는 조용히,
후자는 크게 경고하는 식으로.

## 뒤집을 조건
`reachy.enabled: true` + 연결 실패일 때만 예외로 바꾸는 절충안이 유력합니다.
`enabled: false`는 지금처럼 조용한 mock 유지.
